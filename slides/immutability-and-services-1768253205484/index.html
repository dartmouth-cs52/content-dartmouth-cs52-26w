Supabase
 

🐘 "The Open Source Firebase Alternative"

  • PostgreSQL — full SQL support, not just JSON
  • Row Level Security — fine-grained access control
  • Realtime subscriptions — listen to database changes
  • Self-hostable — run your own instance
  • Auth, Storage, Edge Functions — full platform
// Supabase realtime subscription
const channel = supabase
  .channel('notes')
  .on('postgres_changes', { event: '*', schema: 'public', table: 'notes' },
    (payload) => setNotes(prev => [...prev, payload.new])
  )
  .subscribe();
* great if you already know SQL * more traditional relational data model * very popular, good docs

CRDTs
 

Conflict-free Replicated Data Types
* advanced topic but important for understanding collaborative editing * used by Figma, Linear, Notion
 
The Problem: Last Write Wins
 

What happens when two users edit the same note simultaneously?

  • User A changes title to "Meeting Notes"
  • User B changes title to "Project Ideas"
  • Both send updates at the same time...

⚠️ With Firebase: One user's changes get overwritten!

This is called "Last Write Wins" — whoever's update arrives last, wins.

* this is actually a huge problem in collaborative apps * imagine losing your work because someone else saved * Firebase doesn't solve this automatically
 
CRDTs: The Solution
 

CRDTs = data structures where concurrent edits always merge automatically

  • No conflicts — mathematically impossible to have conflicts
  • No coordination — each client edits independently
  • Eventually consistent — all clients converge to same state
  • Offline-first — works without network, syncs later

The CRDT handles merging locally, then you use Firebase (or any transport) to sync changes between clients.

* this is actually really elegant computer science * the math guarantees no conflicts * offline support comes for free
 
How CRDTs Work (simplified)
 

Instead of storing just the value, CRDTs track operations with metadata:

  • Unique IDs — every operation has a globally unique identifier
  • Timestamps/Vector clocks — ordering information
  • Merge rules — deterministic way to combine concurrent edits
// Conceptually, instead of:
note.title = "New Title"

// CRDTs track:
{ op: "set", field: "title", value: "New Title",
  id: "abc123", timestamp: 1234567890, author: "user-A" }
* this is a simplification but captures the idea * the metadata lets you merge deterministically * same operations in any order = same result
 
CRDT Libraries
 

You don't have to implement CRDTs yourself! Libraries do the hard work:

  • Y.js — most popular, great ecosystem, used by many editors
  • Automerge — JSON-like API, great for documents
  • Loro — Rust/WASM, built-in version control, moveable trees & lists
  • json-joy — JSON CRDT implementation

These handle the complexity — you just use familiar APIs and they sync automatically.

// Loro example
const doc = new LoroDoc();
const list = doc.getList('notes');
list.push({ title: 'Hello', content: '...' });

// Export & sync: doc.export({ mode: "update" })
* Y.js is the most used, huge ecosystem * Automerge has a really nice API, backed by Ink & Switch research * Loro is the newest — written in Rust, compiled to WASM * Loro has unique features: moveable tree (drag notes), built-in time travel (checkout any version like git) * Loro uses the Fugue algorithm for text - fewer merge anomalies than Y.js or Automerge * extra credit to add this to your notes app!
