CRUD API

We’ll be using an API server running at https://platform-api.cs52.me/api

The API has the following endpoints:

  • GET /api/posts/ returns only title, tags, and id for all posts, not content [[{"id":"",title":"","tags":"", "coverUrl":""},...]
  • POST /api/posts/ with post parameters {'title', 'tags', 'content', 'coverUrl'} creates a new post
  • PUT /api/posts/:postID with parameters {'title', 'tags', 'content', 'coverUrl'} will update an entry
  • GET /api/posts/:postID returns the full post data found at postID, including content
  • DELETE /api/posts/:postID deletes the post found at postID

API key

For each of these you need to append an api key. This key can just be your firstinitial_lastname. You can test the api using insomnia or curl.

Choose Your Data Strategy

You have two options for how to fetch data from the API and manage server state. Pick one! Both are real-world patterns used in production apps.

Option A: React Router Data Mode

Data mode unlocks loaders (data fetching before your component renders) and actions (form-based mutations with automatic revalidation). No more useEffect for fetching! You don't need to install anything new — react-router already supports this.

React Router Data Mode Docs

Step 1: Refactor Routes

Replace BrowserRouter with createBrowserRouter + RouterProvider. Your App component becomes a layout route using <Outlet />:

import { createBrowserRouter, RouterProvider } from 'react-router';

const router = createBrowserRouter([
  {
    Component: App,       // App renders NavBar + <Outlet />
    ErrorBoundary: ErrorPage,
    children: [
      { index: true, loader: postsLoader, Component: Posts },
      { path: 'posts/new', action: createPostAction, Component: NewPost },

      { path: '*', Component: () => <div>post not found</div> },
    ],
  },
]);

createRoot(document.getElementById('root')).render(
  <RouterProvider router={router} />
);

// App.jsx — now uses Outlet instead of Routes

  return <div><NavBar /><Outlet /></div>;

Step 3: Add Actions + Forms

Actions handle mutations (create, update, delete). Use the <Form> component from react-router — it submits via fetch and triggers the matching route's action:

JavaScript
123456789101112131415161718192021222324252627
import { Form, redirect, useActionData, useNavigation } from 'react-router';

export async function createPostAction({ request }) {
  const formData = await request.formData();
  const post = Object.fromEntries(formData);
  const response = await fetch(`${ROOT_URL}/posts${API_KEY}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(post),
  });
  if (!response.ok) return { error: 'Failed to create post' };
  return redirect('/');  // navigate home, all loaders re-run!
}

// NewPost component — just a <Form>, no onSubmit handler needed
function NewPost() {
  const actionData = useActionData();
  const navigation = useNavigation();
  return (
    <Form method="post">
      {actionData?.error && <p className="error">{actionData.error}</p>}
      <input name="title" placeholder="Title" required />
      <textarea name="content" placeholder="Content" required />
      <input name="tags" placeholder="Tags" />
      <input name="coverUrl" placeholder="Cover URL" />
      <button disabled={navigation.state === 'submitting'}>Create</button>
    </Form>
  );
}

After any action completes, all active loaders automatically re-run. Create a post? The list refreshes. Delete a post? Same thing. No manual refetching needed!

For delete, create a separate action that calls DELETE on the API and returns redirect('/'). You can trigger it from a button using a small <Form> with method="post" pointed at a delete route, or use useFetcher for inline actions without navigation.

Option B: TanStack Query

Step 2: Fetch with useQuery

Replace useEffect + Zustand fetching with useQuery. It handles loading, errors, caching, and refetching for you:

JavaScript
12345678910111213141516171819
import { useQuery } from '@tanstack/react-query';
import axios from 'axios';

const ROOT_URL = 'https://platform-api.cs52.me/api';
const API_KEY = '?key=yourfirstname_yourlastname';

function Posts() {
  const { data: posts, isPending, error } = useQuery({
    queryKey: ['posts'],
    queryFn: () => axios.get(`${ROOT_URL}/posts${API_KEY}`).then(r => r.data),
  });

  if (isPending) return <div>Loading...</div>;
  if (error) return <div>Error loading posts</div>;

  return posts.map(post => (
    <Link key={post.id} to={`/posts/${post.id}`}>{post.title}</Link>
  ));
}

The queryKey identifies this data in the cache. For a single post, use queryKey: ['posts', postID] and useParams() to get the ID.

Step 3: Mutate with useMutation

Use useMutation for create, update, and delete. After success, invalidateQueries tells TanStack Query to refetch stale data:

JavaScript
1234567891011121314151617181920
import { useMutation, useQueryClient } from '@tanstack/react-query';

function NewPost() {
  const navigate = useNavigate();
  const queryClient = useQueryClient();

  const { mutate, isPending } = useMutation({
    mutationFn: (post) => axios.post(`${ROOT_URL}/posts${API_KEY}`, post),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['posts'] });
      navigate('/');
    },
  });

  const handleSubmit = (e) => {
    e.preventDefault();
    // gather your form fields into an object
    mutate({ title, content, tags, coverUrl });
  };
  // ... render your form with onSubmit={handleSubmit}
}

Follow the same pattern for update (axios.put) and delete (axios.delete). Always invalidateQueries on success to keep the cache fresh.

Zustand for Client State (Both Options)

Regardless of which data strategy you chose, use Zustand for client-side UI state — state that doesn't come from the server. This gives you a clean separation:

  • Server state (posts from the API) = loaders or TanStack Query
  • Client state (what the user is doing right now) = Zustand

Create a uiSlice for:

  • Edit draft state — form fields while editing a post, so you can cancel/discard unsaved changes
  • Search/filter — current search term, active tag filter
  • Sort preferences — how the post list is ordered (newest, oldest, alphabetical)
JavaScript
123456789101112131415
export default function createUiSlice(set) {
  return {
    // edit draft — track unsaved form changes
    editDraft: {},
    setEditDraft: (draft) => set(({ uiSlice }) => { uiSlice.editDraft = draft; }),
    clearEditDraft: () => set(({ uiSlice }) => { uiSlice.editDraft = {}; }),

    // search and filter
    searchTerm: '',
    setSearchTerm: (term) => set(({ uiSlice }) => { uiSlice.searchTerm = term; }),
    tagFilter: '',
    setTagFilter: (tag) => set(({ uiSlice }) => { uiSlice.tagFilter = tag; }),
    sortOrder: 'newest',
    setSortOrder: (order) => set(({ uiSlice }) => { uiSlice.sortOrder = order; }),
  };
}

Use the filter/sort state in your Posts component to filter and sort the post list before rendering. The edit draft state is useful in your Post edit view — store field changes in Zustand so you can implement cancel/discard.

Error Handling

NEVER just console.log an error and move on. Silent fails are the worst — if the user does something wrong and nothing happens, they have no idea what went wrong. Always let the user know!

🚀 Add react-toastify to your project for user-visible error messages.

Terminal
npm install react-toastify

Option A (Data Mode): Use ErrorBoundary components on your routes for structural errors (404s, server failures). Use toasts for user-facing feedback on actions.

Option B (TanStack Query): Use try/catch in your mutation callbacks and toast the error. TanStack Query also provides error states from useQuery that you should display.

Either way: try/catch your API calls and toast errors. Don't be bad.
