What are we building?!

A post it note style app where users can add notes, move them around, edit them, and delete them. This React app will use Firebase as its backend to store collections of notes. The position of notes will also be stored, so people in multiple browsers can edit and arrange them in realtime. The notes themselves will support markdown notation and editing.

Here are the overall specs of the full project.

Minimal Functional Specs

  • Notes App:
    • Add a note:
      • can either be a single title input + create button
      • or a modal if you prefer with all fields
    • Delete a note
    • Move a note in x, y
      • optionally in z (zIndex)
    • Edit a note:
      • title, content
    • Notes:
      • have title and content
      • display with some formatting
    • Persists all changes to Firebase in realtime
    • Updates based on Firebase events
    • is at least as stylish as these mockups

Note: you are welcome to use CSS frameworks to help with styling (but be careful as the JS that comes with some of them does not play nice with react).

Lab 3: React Notes

Part 1: Local State Dataflow

🚀 For Part 1, draw out the dataflow for a single-user, local state version of the app. This is where notes live in React state only — no backend, no persistence. Think about:

  • Where does the notes state live?
  • How do components communicate updates (add, delete, edit, move)?
  • What props flow down? What callbacks flow up?

Part 2: Firebase Dataflow

🚀 For Part 2, extend your dataflow to show how Firebase changes the picture. Now instead of local state, you're subscribing to Firebase events and pushing updates to the cloud. Think about:

  • Where does the Firebase connection get initialized?
  • How does data flow from Firebase → React state → components?
  • When a user edits a note, what's the path from UI → Firebase → other users?
You need both dataflow diagrams! Part 1 shows the simple local flow, Part 2 shows how Firebase changes it.

Optional: AI-Assisted Planning with Claude

This section is optional — only if you're choosing to use AI assistance for the lab. If you're handcrafting your code without AI, skip this section.

If you're using Claude Code to help build your React Notes app, we want you to be intentional about it. No one-shotting the entire assignment. Instead, you'll build incrementally: one feature branch at a time, with a plan file for each feature.

The Workflow: Feature Branches + Plan Files

For each feature you add:

  1. Create a feature branch (e.g., git checkout -b add-notes)
  2. Enter plan mode and create a plan for that feature
  3. Copy the plan file from ~/.claude/plans/ to plans/feature-name.md
  4. Implement the feature following the plan
  5. Commit and merge the feature branch
  6. Repeat for the next feature
Do not one-shot this assignment. We want to see your thinking process as you build incrementally. Each feature should have its own plan file.

What is Plan Mode?

Plan Mode is a special mode in Claude Code where Claude can only read and analyze your codebase — it cannot make changes. This forces you to think through the approach before any code gets written.

Terminal
claude
# then type:
/plan

Saving Your Plan Files

Claude Code stores plan files globally in ~/.claude/plans/, not in your project. To include them in your repo, copy them to a plans/ folder and name them after your feature branch:

Terminal
# Create a plans folder in your project
mkdir -p plans

# Copy your plan file, naming it after the feature branch
cp ~/.claude/plans/your-plan-file.md plans/add-notes.md

# You can view your current plan with /plan in Claude Code
# Or list all plans with:
ls ~/.claude/plans/

What Each Plan File Should Include

  • What problem/feature this branch addresses
  • What components or files will be created/modified
  • Key implementation decisions and why
  • How this feature connects to existing code
The goal is to understand the plan, not just generate it. Ask Claude "why?" at each step. If something doesn't make sense, dig in before moving on.
